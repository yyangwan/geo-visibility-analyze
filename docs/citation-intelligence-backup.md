# 引用分析备份包与迁移互斥

2026-10-16，第26批，本地实现。真实MySQL/OSS资源、恢复导入与恢复演练尚未验收。

## 本批能力范围

工具把**分析后端专用数据库**的全部已登记表，以及该数据库快照引用的不可变OSS正文对象，导出为一个可核验的本地备份包。覆盖完整回答、原始响应、引用观测、分析修订、来源正文、人工审批、复测等后端数据库记录；不是只备份最近两次审计。

当前54张应用表和alembic_version共55个表文件。Portal的PostgreSQL、ContentOS数据库及内容附件、运行环境配置和密钥文件不在这个包内；整个产品的跨服务联合恢复仍未完成。平台诊断页继续显示备份恢复「未接入」，不会因为存在CLI就展示恢复成功。

## 一致性与互斥

- 所有在线Alembic迁移与数据库导出，共用同一MySQL实例、同一数据库的GET_LOCK会话锁，默认等待60秒。锁名由数据库名的hash派生，不输出数据库名。未取得锁或结果未知即拒绝执行。
- 锁在同一条连接上贯穿操作，获取后先COMMIT清除SQLAlchemy的隐式读取事务，再交由Alembic管理事务；MySQL命名锁不会被COMMIT释放。成功或失败均清理锁，释放不能确认时废弃连接，不归还连接池。MySQL DDL不是整批原子事务，失败仍需要核对revision与实际结构。
- 锁为MySQL实例本地锁，所有执行器必须连同一主实例，不支持跨多主实例/连接多路复用代理的全局互斥；不能约束绕开此入口的手工SQL。仅生成离线SQL不连接数据库、不取得锁。
- 导出要求表清单和列名清单与当前代码完全一致，数据库revision等于当前head，且全部表为InnoDB。只支持专用数据库；发现额外或缺失表/列即失败，避免漏备份未知数据。这不替代全面的数据库结构漂移审计。
- 一个REPEATABLE READ事务读取全部表，首次读取revision建立数据快照；正文对象引用也来自该事务。业务DML可继续提交，后续提交不混入包。数据库读取阶段持锁，提交后释放；对象复制阶段不长期占用数据库快照。
- 对象按快照内的key/SHA实际读取并校验字节，项目路径必须与project_id一致。同SHA对象只保存一份字节，但每个引用key都必须实际读取，缺失的第二个key不能被第一份内容掩盖。ETag或HEAD元数据不能替代实际SHA核验。

## 操作入口

在已授权的备份运行环境、backend目录执行，使用环境中的数据库连接与ECS角色临时凭证，不在命令行传密码或密钥。导出会读取真实对象，产生存储读取/流量费用；本轮开发只在虚构本地测试数据上执行，没有调用真实资源。

```sh
python -m app.intelligence.backup export --output /private-backups/new-backup-id
python -m app.intelligence.backup verify --directory /private-backups/new-backup-id
```

父目录需存在，输出目录必须全新。不会覆盖已有目录，不会自动清理旧备份或改写数据库。导出账号按只读权限配置；存储要求现有私有Bucket、禁版本控制及对象GET权限。迁移继续使用`python -m alembic upgrade head`，在线入口现已自动加锁，不需更换命令。

生产输出目录必须位于访问受控、加密的专用卷。POSIX目录/文件使用0700/0600；Windows的chmod不保证NTFS访问隔离，需预先配置ACL。**备份含完整业务数据，数据库表内也可能含敏感字段**，不可加入git、公开下载、CI artifacts或普通日志；终端只返回随机备份ID、表数、对象数及结果，不输出key、来源、SQL/SDK异常或数据内容。运行配置文件、`.env`和`.keys`不由工具复制。

## 文件与校验

- `database/<固定表名>.jsonl`：流式写入，所有列按明确类型标签保存；datetime/date/time/Decimal/bytes、Unicode及原始JSON结构保留，不以JSON里的`t/v`字段误认类型。每表含列清单、行数和文件SHA。
- `objects/<SHA>.bin`：原封不动保存压缩对象字节，不重新提取、解压或改写正文。
- `manifest.json`：格式citation-backup-1、当前revision、全部表清单、key/SHA/文件/长度映射、生成时间和备份ID。对象key只存在于私有包，不在终端返回。
- `INCOMPLETE`：创建目录后立即写入；所有表、引用和对象校验通过后才移除此标记。中断或失败保留部分包，校验器拒绝将它当作完整备份，不自动递归删除。

校验器重新解析每行、核对列数/类型编码、表行数与SHA、revision，以及从已备份快照重新推导的对象引用；拒绝重复/缺失表、路径逃逸、额外/缺失引用、错误长度/SHA和不完整包。最终返回`bundle_verified`，`restore_test`仍为`not_performed`。这是文件完整性校验，不是签名认证、数据库恢复或业务恢复验收；需保证包的来源可信，不能以可改写清单替代可信异地存储。

## 恢复与保留：尚待实施

本工具没有数据库导入、覆盖或清理入口。下一步需要实现：只允许独立新恢复库的导入执行器、类型/外键及逻辑引用校验、恢复正文到独立私有Bucket、任务租约与旧进程隔离、恢复后报告/证据/审批/复测回查，以及Portal/ContentOS同一恢复窗口的协调。

备份包自带正文副本，生成后不依赖源Bucket继续保留这些key；但生成过程中仍要求源对象存在且不可变。目前没有对象GC，不会自动删除源对象。未来实施引用感知保留/过期和GC时，必须保护正在生成的备份、数据库备份恢复窗口及所有有效引用，并把备份清单纳入审计；不能直接启用Bucket生命周期删除、版本控制或按容量清理。

异地加密上传、计划调度、校验状态持久化、告警、恢复窗口保护和真实恢复演练仍未实现。不能据本地单元测试宣称MySQL并发或真实云环境已验收。
