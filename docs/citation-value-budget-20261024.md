# 分阶段分析预算与恢复验收

状态：B03 预算与恢复基础链路已实现并在本地验证；未发布。语境分析阶段仅预留额度，A02 第二遍分析仍待接入；本记录不代表整个审计分析方案完成或语义质量达标。

## 预算如何保护分析完整度

每个 Run 冻结 `analysis_budget`，请求与 token 都有总上限。默认环境配置分别为 `AISCOPE_INTELLIGENCE_MODEL_REQUEST_LIMIT=500`、`AISCOPE_INTELLIGENCE_MODEL_TOKEN_LIMIT=10000000`；这是运行保护上限，不是调用目标或费用承诺。配置有非负及最大值检查。

`analysis-budget-v1` 将总额度预留给通用抽取 60%、语境分析 25%、证据核验 15%。取整保持总量不增加，小预算优先基础回答。通用抽取内，先按冻结回答的实际去重片段和保守 token 估计预留，剩余给来源卡片/正文；来源不能占用后两阶段的预留。不会为只有几条回答的审计固定闲置数百次请求额度。

回答片段仍按各自平台/owner 保存；文本重复只减少实际 provider 请求，不减少观察样本或评分分母。评分规则、问题资格和采集轮次不因预算变化而改变。

## 调用与结算

- 调用前，在现有 JobQueue 行锁、租约和 fencing 检查点内预留请求及预计 token，保存 receipt、阶段、subject ID 和租约版本，不保存提示词或凭证。
- 估计采用输入 UTF-8 字节数、已约束的输出上限和消息余量；它是保守预留，不冒称等于供应商 tokenizer 或账单。实际接口用量只保留合法非负整数 `prompt_tokens` / `completion_tokens`。
- 成功结果与用量在同一数据库检查点落库；供应商给出合法计数时按实际值结算。JSON/语义格式失败但已取得合法 usage 时也记录实际消耗。
- 超时、传输错误或缺少可靠 usage 时，按整笔预留占用，不能以 0 消耗恢复额度。供应商报告超出估计则如实记录，并阻止该阶段继续超过上限。
- settlement 可重复提交同一结果，冲突值被拒绝；旧租约不能覆盖新账本。新 worker 将旧租约未结算记录归为用量不明，保留额度，不把它们永远显示为进行中。
- 外部调用超时后无法证明供应商是否执行，不能承诺供应商端 exactly-once；已有结果缓存和已写入的应用/核验结果会复用，未知窗口保持保守记账。

## 延后与继续

额度不足不会生成“已完成但未提及”的假结论。Run coverage 返回 `model_budget` 的阶段用量以及 `deferred_operations`，逐项保留阶段、材料/片段标识和 `phase_request_limit` / `phase_token_limit` / `analysis_provider_unconfigured` 原因。

七类就绪状态会明确区分额度不足、未配置服务和片段待核实。管理员调整配置后，由现有分析创建入口生成新的冻结修订；不会提高旧 Run 的额度或覆盖它的证据。新修订复用同项目、同文字及分析签名的结果缓存，已完成部分不重复调用。不自动重采设备数据，也不改写历史数据。
