# 引用分析质量评测与独立标注

2026-10-16，第27批，本地实现。当前交付是可重复运行的评测工具、私有样本导出和中文报告；不是已完成100组真实留出样本的人工验收，也不是模型已达到95%目标。

## 解决什么问题

分别检查：

1. **实体误报与漏报**：完整回答、来源摘要、文章段落中，哪些品牌/组织/产品/人物被遗漏或错识别。不依赖自有/竞品名单，不把正文品牌出现算成回答提及。
2. **观点与证据关系**：模型给出的支持、部分支持、矛盾或待核实，是否与两位独立标注者对所选证据片段的判断一致。
3. **引用链归属**：支持结论是否确实来自同一回答、同一平台的实际引用，快照/来源对应、逐字证据和采集状态是否有效。搜索候选即使内容支持，也不能算已验证的实际引用。

分层为分析签名×平台×任务×回答/摘要/正文×来源类型×采集状态×development/holdout×数据来源。不同模型/提示/规则版本不合并；合成与真实审计记录分开。实体另按kind给精度/召回。问题簇跨平台、轮次、审计及项目按同一prompt_hash归组，不能把同题多个回答当成独立问题数。

## 第一步：导出近期私有审计

在backend目录、已授权的运行环境操作；使用环境中的只读数据库权限，不在终端传密码，不导出到仓库、公共目录或CI artifacts：

```sh
python -m app.intelligence.evaluation_export export \
  --project-id <项目ID> --audit-limit 2 --split holdout \
  --output /private-evaluation/new-dataset
```

范围只允许最近1或2次审计。每次审计选择最新的**全部状态**修订；最新queued/running/failed时记录该状态，不回退旧成功Run。无Run、来源受限、缺少正文或缺段有明确统计，不被当成负样本。只读DB已保存的段落、语义缓存和观点对；不会创建任务、补抓正文、调用模型、访问OSS、批准材料或改写审计。

当前版本支持unicode-nonoverlap-1分段。段落实际SHA必须匹配，语义缓存必须对应同一项目、文本hash和Run分析签名；未完成或缺少缓存记为missing/deferred，不能预填成模型识别到零个实体。导出含所有适用段落及长回答尾部。最多10000个段落/观点对/样本，超限明确失败，不静默抽样；可先缩小到最近一次审计。

文件含：

- `cases.jsonl`：私有原文、当前段落相对位置、全文global_offset、回答观点、模型所选证据片段及冻结作用域。关系样本不展示模型的relation分类，但必须展示其选取的证据片段，才能评价这段证据是否支持观点。
- `predictions.jsonl`：独立保存模型输出及版本/input hash，**不交给标注者**。
- 两个`annotations-*.template.jsonl`：默认pending、entities/relation均null；不复制模型实体、情感或关系充当人工答案。
- `ANNOTATION_GUIDE.md`：偏移、实体、关系、双人独立标注和留出规则。
- `manifest.json`：选择的audit/run/revision、回答/抓取状态分布、缺失正文/段落、已有观点处理覆盖和文件SHA。目录已存在则拒绝覆盖，未完成包保留INCOMPLETE。

段落来自数据库，导出时核验段落SHA；不代表同时重新核验OSS压缩对象或确认文章已完整采集。不同引用卡片共享同一正文时保留各自observation_id，不能因为内容相同就丢失平台/引用观测。

## 第二步：两位独立标注

分别把cases与各自模板交给两位标注者，不让他们查看模型答案或对方标注。使用真实且不同的匿名reviewer_id；工具只能校验ID不同，无法证明两人独立，当前是操作者声明，不能替代服务端实名审核。

实体任务标注全部原文提及：name/kind/quote/start/end/sentiment。start/end是当前text中的Python Unicode字符位置，end不含边界，不加global_offset；quote逐字匹配、name出现在quote中。不存在实体时明确填`[]`并设reviewed，未查看保持null/pending。情感针对单个实体，不把其他品牌情感带过来；不能判断用unknown。

关系任务对照answer_quote、evidence_quote及原文上下文；必须评价**提供的证据片段**，不能用全文其他位置替无关引用补证：supports完整支持，partial限定范围/时间/数字仅部分一致，contradicts明确冲突，unverified不足判断。证据片段缺失或不在原文时不能标为支持/矛盾。source_kind和citation_eligible用于另行检查引用归属，不能因语义支持就把候选变实际引用。

只有同一样本至少两个不同ID的reviewed结果完全一致，才参加语义指标；单人、未标注和分歧单独统计，不投多数票、不用模型补答案。重复标注者、无效原文位置、任务类型错配和过期input hash会拒绝评分。分歧的正式复核事件与实名审计还需后续接入，当前不要通过删改一个人的记录掩盖分歧。

## 第三步：冻结留出边界并评分

曾用于提示词示例、规则调优或开发评测的问题簇group_id，先登记到JSON数组文件。即使换平台、轮次或审计，同题不能进入留出集。工具检查包内development/holdout及显式登记表的交集；不知道曾使用哪些题不等于已经证明无泄漏，操作者仍需维护完整登记。

```sh
python -m app.intelligence.evaluation_export score \
  --directory /private-evaluation/new-dataset \
  --annotations /private-evaluation/review-a.jsonl /private-evaluation/review-b.jsonl \
  --development-groups /private-evaluation/development-groups.json \
  --output-report /private-evaluation/result-v1.json
```

同时生成JSON及同名Markdown报告，文件必须全新。manifest固定cases和predictions的SHA；Case/input/prediction签名、quote及标注作用域再次核验，改写原文或换模型结果不能悄悄沿用旧标签。CLI只返回dataset ID、数量和状态，原文、SDK/SQL异常或标注内容不进终端错误消息。

## 指标如何解读

| 指标 | 分母与边界 |
| --- | --- |
| 实体精度 | 正确的精确提及 / 全部预测提及；匹配name/kind/quote/本地起止位置，重复预测额外计误报 |
| 实体召回 | 正确提及 / 双人一致标注的全部提及；缺失预测计漏报，未标注样本不冒充没有实体 |
| 实体情感准确率 | 正确情感 / 已匹配且人工情感非unknown的提及；不代表全部实体覆盖 |
| 支持精度 | 双人确认支持且引用链/quote有效 / 模型判定supports的已一致标注样本；partial/contradicts/unverified及候选引用不能计正确支持 |
| 关系准确率 | 四类判断正确数 / 双人一致标注的观点对；缺失预测作为missing进入混淆矩阵，unverified另报数量 |
| 覆盖与结构异常 | 未标注/单人/分歧、missing/deferred、无段落/无归档、无效span与引用链错误分别统计；异常即使尚未人工标注也可见 |

所有比率保留分子/分母；分母0显示未评估，不显示0分或100%。每层同时显示样本量及独立问题簇数量，不用很多同题片段伪装很多独立问题。没有综合可见性分数或成功概率。

中文报告按实际错误提示优先核查方向：先修引用/平台串用与证据错位，再处理标注分歧、采集/预算/worker缺失，之后看误报、漏报与观点范围/时间/数字。支持精度低于95%只表示观察值低于方案目标，不是统计合格或发布判定。

第28批根据用户阅读反馈调整Markdown：先解释报告用于检查我们分析系统的可靠性，平台名仅表示输入来源；再逐项用中文说明识别正确/误认/遗漏，以及多少“支持”判断被核对确认。不在主表堆叠平台代码、任务代码、模型hash或单条样本百分比；无品牌内容不当作满分，缺乏一致标注时不评价表现。技术版本放在每项底部追溯，详细字段仍在JSON。评分计算、分层和人工复核边界未改变。

合成样例另提供简短解释版synthetic-report.md，以两个人工编写的原文对照案例说明误认/漏认和错误支持判断；synthetic-report-details.md由通用生成器产生。该解释版包含的品牌/原文均是既有虚构样例，真实报告默认不把私有原文写入评分摘要；要展示真实逐条原文时仍需遵守项目权限和受控回查。
