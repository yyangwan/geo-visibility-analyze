# A01 场景、问题审核及业务偏好实现记录

本轮已按用户确认的局部原型接入正式组件，代码仅在本地分支，未发布生产。场景配置不是完整的竞争机会或内容方案，A02–A05 的语境、材料及机会链路继续实施。

## 当前可用能力

固定八类场景：认知了解、方案与品类选型、功能比较、价格与成本、实施适配、案例与验证、风险限制、售后服务。稳定代码为 `awareness/selection/features/cost/implementation/proof/risk/service`。

- 在冻结问题中逐字匹配词语，产生带 Unicode offset 的场景建议，方法标为 `literal_rules_unreviewed`。没有命中时保持待核对；不会用回答文字或自有材料补写问题需求，也不将建议自动确认。
- 问题范围审核可保存主场景、附加标签、中性/品牌定向/不确定指向、品牌原文、意图及目标客户/使用情境/需求/限制的原文证据。客户表单提供主场景、问题指向及可折叠需求原文；其他结构字段可经同一接口审核保存，未提供保持未知。
- 主场景和指向确认、资格选择、审核依据、操作人、CAS 版本及幂等请求一起保存，生成新的分析修订。旧 Run 不被覆盖。暂不确定可继续保留待审核；未确认主场景不进入对应场景的评分。
- 登记名称的词语命中与品牌身份分开。只有明确“品牌/产品/公司”等指向才固定排除；其他名称命中保留歧义审核路径，例如“苹果价格”。未登记品牌也能通过逐字引用标记为定向问题并排除，不要求先加入品牌库。
- 按已审核主场景与平台投影评分；附加标签不重复增加样本。沿用原冻结权重，在所选范围内显式条件化，缺失平台仍未知。30/30/20/20 固定维度权重不变，不通过重新分配缺失样本权重补分。
- 门户在洞察、品牌对比、平台对照的评分工作区提供场景选择，并将选择保存在 URL；切换视图保留场景。失效/尚未确认的场景不会回退显示全审计分数。其他品牌/平台的全局范围统一仍归 U01 继续实施。

## 偏好持久化

`GET/PUT /api/integration/intelligence/preferences` 经过现有项目、工作空间、权限及能力校验。读取不产生分析任务；写入只允许现有写入角色，客户端不能覆盖其他项目。

保存时锁定 PostgreSQL 项目行，校验配置版本，将 `businessPreferences`、新配置签名及 durable outbox 在同一事务中提交。同内容重试不重复建版本；不同内容的过期写入返回 409。接收端暂不可用时明确返回已保存、待同步，不将成功落库误报为未保存。

八类重要性支持低/中/高（25/50/100），接口保留 0–100 整数契约，拒绝未知场景、布尔值和评分权重覆盖。默认场景等权 50；恢复默认也保留设置理由和新版本。缺少场景配置不宣称掌握客户业务优先级。

偏好不修改旧 Run 分数或资格分母，也不触发采集/模型调用。当前提供配置及 `priority_policy_version`，将由 A05 的机会排序投影消费；本轮不声称既有建议已经按新偏好重排。

## 数据与接口

复用 `EvaluationCohortReview.cohort` 保存 `question-context-v1`，无新增表、无 schema 升级。冻结范围版本为 `brand-cohort-v2`；纯文字抽取签名与缓存仍可复用。

- `GET /runs/{id}/evaluation-cohort` 增加场景字典和审核摘要。
- `POST /runs/{id}/evaluation-cohort/review` 接收按冻结 prompt hash 的 `contexts`，校验全部问题范围及逐字位置。
- `GET /runs/{id}/scenarios` 返回已确认主场景、问题上下文和按品牌目标/平台的范围分数。
- Run detail 增加只读 `summary.scenario_comparison`；读取失败 Run 也不会改写其 summary 或添加任务。
- `GET /projects/{id}/scenario-preferences` 返回接收端偏好与策略版本；配置主写仍在门户。
