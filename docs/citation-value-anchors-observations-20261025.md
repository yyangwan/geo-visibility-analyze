# A04 引用锚点、核验覆盖与逐次来源观察

本轮完成分析后端实现，使用已确认 v3 的证据与来源数据方向；没有页面样式或网关改动，尚未上线。门户消费新增下钻信息仍属于 U02，机会与具体任务包仍属于 A05。

## 修正的问题

原实现把 `CitationObservation.anchor` 留在采集表中，未冻结进 Run。V2 的锚点是两个 Unicode code point 偏移，旧读取分支却按字典判断；核验默认给同回答的每条观点遍历全部实际引用，每来源只看前五个相关段落，未检查范围不明确。

新流程保留实际采集身份和原文证据链，不把“同一篇文章”“检索候选”或“模型判断”直接升级成实际引用、独立证据或已批准事实。

## 冻结及关联

- manifest 来源记录现在含引用 ordinal、锚点状态、回答 hash、逐字锚点范围和实际正文版本（snapshot/body hash/representation/extractor/integrity/completeness）。锚点范围按 Unicode code point 校验，不接受布尔值或浮点数转换为偏移。
- 只有本 Run 已选定的采集回答对应的观察进入 manifest，未选中重试结果不会混入新修订。
- 明确且有效的锚点只关联与其重叠的观点；落在其他观点的引用不会串文。已冻结锚点的回答 hash/逐字文字不符时拒绝关联。
- 没采到锚点或原始锚点无效时，保留原因并使用 `same_answer_fallback`，披露这是推断关联。仍严格限制在同回答、同平台、确切 URL 的 `answer_reference`；`search_candidate`、未知分类、推断 URL 不能证明该观点有实际引用支持。
- 现有网关 `capture-v2.ps1` 默认 `answerAnchor = null`。本轮没有增加网关锚点采集，当前这类数据会走明确回退，不能声称已经获得精确的采集锚点。

## 候选与未检查范围

策略 `anchored-observation-budget-v2` 按每条观点分配最多 12 个候选对，而非每篇文章默看五段。先覆盖各观察的最佳段落，同轮优先明确锚点，再取下一段；相关度只影响召回排序，不决定支持关系。

核验前验证本 Run 所用的来源片段连续性、Unicode 长度及重建正文 hash，并验证当前快照与冻结版本相符。保存片段有缺口、正文受限或证据不可用时保留具体阻塞，不用标题/摘要冒充正文；原文章完整性未知不否定已保存片段的正面证据。

`coverage.evidence_alignment` 输出：

- 可用/候选/处理/有效检查/延后/无效/未检查对数及策略版本、候选上限。
- 每个观点 × 引用观察对应的回答范围、关联方式、来源版本、可用段数、已选择段落与状态。
- `candidate_excluded_ranges` 表示候选配额以外的正文；`unchecked_ranges` 还包括因阶段预算、未配置接口或无效输出而未有效检查的选中范围。
- 不可用正文与锚点不匹配分别记录原因；没有任何未检查范围时也只代表保存文字的候选检查覆盖，不能证明原网页全文完整。

有未检查候选或无效/延后核验时，Run 保持 partial。回答评分的独立就绪度仍按各自条件判断，不因正文未检查就推断回答中品牌缺席。

## 五维核验与审批边界

关系仍区分 `supports / partial / contradicts / unverified`。接口提示模型分别检查主体、范围、时间、数字和条件；每个维度保留双方逐字引文和关系。不存在的维度文字、重复维度或虚构引文被拒绝，不使用外部知识补证。

逐维度发现的明确冲突会覆盖矛盾的总体“支持”判断，部分支持也不能保留为完整支持。时间不一致本身不被规则自动断言为事实冲突。没有返回的维度保持未检查，不补成支持。

来源主引文必须能唯一定位到保存片段；重复片段不猜第一次出现。`ClaimEvidence.verification` 持久化关联、回答/来源 code point 范围、逐维度结果、输入 hash 和核验策略。结果、实际用量与写入仍处于同一租约 fencing 检查事务；旧租约不能追加结果。具名审核重新检查冻结锚点、平台、快照版本和范围，批准事实仍走现有人工作业链。

同 Run 中完全相同的“观点文字 × 来源片段 × 模型/接口/核验策略”可以复用已经保存的核验结果，保留每条引用独立记录，并标明 `same_text_reuse`。不重复请求或结算；不跨项目复用，不宣称新修订的全部核验已具备全局缓存。

## 文章归并与内容重复族

新 `summary.source_observations` 和报告投影按文章归并，但每条观察独立保留平台、回答、引用类型、正文版本和锚点。某平台实际引用与另一平台检索候选不会合成一个“实际引用”的标签。

完整性验证通过的保存文字以正文 hash 合并完全重复内容；长度至少 200 的文字可用 5 字符频次片段的 90% 相似度和 80% 长度比筛选高度相似转载候选。比较最多 20,000 对，超限明确标 partial。相似度只说明“重复候选”，不证明作者、转载顺序或编辑独立性。

同观点、同内容族、相同关系只保留一份 `deduplicated_content_weight`；重复观点不会累加证据。不同解释都保留，出现关系分歧时整组权重为零并标记 `conflicting_interpretations`，交由审核，不做多数投票。unverified 或无效结果不加权。此字段供后续机会排序消费，不修改固定可见性评分。

`actual_reference_content_families` 是已归并内容族数；真实独立发布方数量 `independent_publishers` 保持 null。不同网址或域名不自动等于独立事实来源。

## 接口及结构

新增只读 `GET /api/intelligence/runs/{run_id}/source-observations`，支持 document_id、platform、offset、limit（至多 100）。沿用同项目授权，读取已保存投影，不采集、不调用模型、不创建任务。来源原文仍通过现有 Run 内容权限接口读取。

最新空库基线增加 `intelligence_claim_evidence.verification` JSON 列，表数仍为 58；新增测试检查静态基线的所有列与模型一致。没有旧库升级或历史兼容逻辑。部署前必须使用本轮最新空库结构；现有旧测试库没有被修改、清空或迁移。
