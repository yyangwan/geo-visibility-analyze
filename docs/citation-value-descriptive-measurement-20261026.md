# M01 单轮描述复测

本轮完成后端与门户显式代理合同，不改正式页面样式。M02发布关联、U04页面和真实客户价值验收仍为后续任务。数据库结构未变，沿用citation_execution_20261026、60张业务表；没有迁移、历史回填、生产部署或真实模型调用。

## 冻结合同

POST `/api/intelligence/projects/{project_id}/cohorts`新增明确的`comparisonMode: descriptive_v1`，使用`brandTargetIds`以及可选`platforms`/`promptHashes`。模式不接受`entityIds`。登记品牌使用registry目标，即使基线没有提取到实体也能选择；未登记品牌使用entity目标。创建后不能切换模式或范围，须另建cohort。

cohort冻结指标版本`brand-observation-descriptive-1`、评分规则brand-visibility-v1及固定权重、身份/条件策略版本、目标身份和名称范围、问题/平台、第一轮样本、场景审核范围、原基线品牌观察哈希及输入/分析签名。所有内容进入specification_hash。既有inferential_v1保持独立，20题×3轮门槛不变。每个cohort的结果唯一键与比较签名共同隔离不同规范。

descriptive复测只创建冻结的问题/平台第一轮样本。额外轮次不能扩大比较范围。方案、复测和计算结果都以当前加锁读取处理幂等重试；真实MySQL重复读的旧快照不会重复受理。

## 观察及可比性

逐题逐平台逐品牌返回出现、推荐、明确位置、选择理由，以及实际引用卡片、已保存引用正文、检索候选卡片三类独立来源指标。出现及来源指标单位为0/1；其余沿用固定规则的0–100分项。指标保留原回答、提及证据及来源原文索引，不把候选来源当作实际引用，也不把来源正文出现当作模型使用证明。

| 情况 | 输出 |
| --- | --- |
| 目标、原问题/平台/分析规则及已知条件一致，前后值明确 | comparable，可返回observed_delta |
| 某些实际采集条件未知，未发现明确变化 | conditions_unverified，保留双方事实，无差值 |
| 任一明确条件、规则、问题或身份范围变化 | incompatible，列原因，无差值 |
| 样本不全、对应不唯一、某维度未观察或证据不足 | missing，保留已取得事实，未知不补零 |

明确变化优先于其他未知条件。部分正文/来源面板中已看到的正向事实仍保留，但不成为完整可比较样本。位置未核实不补零，原文归属待核实不比较，同一单元的重复品牌观察不能变成零或正向效果。

登记品牌的稳定目标和名称范围一致时，已确认缺席的空entityId可与首次确认出现配对。实体编号改变需要明确人工等价合并及确认的目标身份；保留前后实际目标编号和等价事件。名称范围扩展、角色变化、未核实身份或替换主体都会阻断差值。

单轮模式不返回difference/interval95、显著性、改善总分或因果归因。各平台及退化独立保留，不用均值掩盖；点击、转化、ROI仍未知。

## 保存结果及当前有效性

同一保存/报告投影应用于结果POST、结果GET、measurement-history及报告。原结果不变，读取时核对cohort和Run关联，相关变化后将observed_delta清空。

首次确认出现会改变项目身份配置，旧基线可能不再通过全局stamp。单轮模式可在复测当前有效且基线没有新修订、原品牌观察哈希一致、原问题审核与原文归属仍有效时，保留冻结的旧缺席观察。输出baseline_snapshot_current、followup_snapshot_current和freshness_basis，区分冻结基线与当前复测。新分析修订或相关原文归属/问题变化仍会撤下差值；不能用原空entityId永久锁死首次出现的观察。
